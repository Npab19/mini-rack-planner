and green: type-check, unit and property tests, lint, header and catalog checks, build, bundle
budgets, the Docker image under Playwright, and the spike checks. The golden numbers for your rack
come out exactly as planned. What is left needs you: the KWS files and measurements, your device

for that exists (S1); the import screens come in M5 and M7.

## What exists now

### M0: foundations

- **App shell.** Vite 8, React 19.3, TypeScript 6.0.3, Tailwind 4 and shadcn on Base UI. React
  Router data routes, each page lazy: Plans, Editor, Compare, Viewer, Import, Library, Settings,
  About and 404. The pages are placeholders until M2/M3; About shows the version and commit.
  The dev spike pages (`/dev/spike-dnd`, `/dev/spike-worker`) exist only in dev and in
  `VITE_SPIKES=1` builds.
- **Type and lint gates.** Four tsconfigs (app with DOM; worker with the WebWorker lib, which also
  keeps `src/domain` and `src/lib/shared` DOM-free; node for scripts and configs; test). oxlint
  enforces the boundaries: no React, Dexie, Zustand or three in `src/domain`, relative imports
  inside it, and three, R3F and meshoptimizer only in `src/features/viewer3d` and `src/workers`.
- **Security headers from one source**, `scripts/headers.ts`: the nginx snippet, the SWA
  `globalHeaders` and the Vite preview headers, with a drift check.
- **Docker.** Multi-stage build to `nginx-unprivileged:1.30-alpine` on port 8080, read-only root
  filesystem, `/healthz`, immutable `/assets/` caching, a 404 for missing assets, and a Compose
  file.
- **CI/CD.** `ci.yml` (model-file guard, type-check, lint, tests, header and catalog checks, build,
  budgets, then the Docker image under Playwright), `azure-swa.yml` (deploys only once the token
  secret exists), `docker-publish.yml` (GHCR amd64, arm64 and arm/v7), `release-please.yml`,
  `nightly.yml` (Firefox and WebKit, `npm audit`), Dependabot, issue and PR templates, CODEOWNERS
  and [deploy.md](../deploy.md).

### M1: domain, catalog and BOM

- **`src/domain`**, pure TypeScript, described in [src/domain/README.md](../../src/domain/README.md):
  - geometry in sixths of a U; zod schemas for catalog entries, plans (schema 1), settings and
    alignment records; entry integrity checks;
  - recipes with quantity formulas, conditions and layered options, and embedded hardware;
  - stack operations (insert, remove, move, split, merge, `setHeight`, retire, mark as Have) with
    `remap` and conflicts; placement phases, snapping, occupancy, `canPlace`, `fitItIn` and slot
    packing;
  - the BOM (target against as-built, spares, packs, rack screws, provenance, the designer-table
    note, inventory use); checks; the power budget; 3D part instances (proxies);
  - share links (codec 1, template and show-off modes, size caps); migrations with typed errors.
- **Catalog**: 78 entries (2 frames, 13 items, 20 devices, 43 hardware), generated JSON Schemas,
  `ids.lock`, `replaced.json`, and `npm run validate-catalog`. The app bundles it with
  `import.meta.glob`; Node scripts read the same files through the same parser.
- **BOM CLI**: `npm run bom -- <plan.json>` with `--full`, `--json`, `--spares` and `--out`.
- **Fixtures**: four KWS golden plans with their expected shopping lists, plus frozen schema-1
  compat fixtures (see [fixtures/README.md](../../fixtures/README.md)).

## Spike decisions

- **S1, 3MF/STL structure (core done; real-file answers pending).** A DOM-free parser in
  `src/lib/shared/model` reads MakerWorld/Bambu, Orca and Prusa 3MF, plain 3MF, binary and ASCII
  STL, and ZIPs of them, with zip-bomb and size caps, the `g1` geometry key and a signature. It is
  tested on synthetic files only (500,000 triangles parse in about 0.5 s). The questions for the
  real KWS files (objects or islands per plate, mirrored legs, slice info, units, transforms, the
  7 base magnets) are listed in [s1-3mf-structure.md](../spikes/s1-3mf-structure.md) and need
  your downloads.
- **S2, drag and drop (decided).** Keep `@dnd-kit/react` 0.5 for palette → rack drops only, behind
  a `useRackDnd` adapter. Placed items move with Pointer Events and pointer capture, keyboard moves
  and tap-to-place are our own code, and the target U always comes from
  `svg.getScreenCTM().inverse()` plus pure snapping. Exact at 50/100/200 % zoom, on touch and under
  the production CSP. Use the viewBox camera; keep dnd-kit's Feedback off for SVG nodes and the
  overlay out of the layout flow. See [s2-dnd.md](../spikes/s2-dnd.md).
- **S3, hand-aligned KWS parts in 3D: not started.** It needs your KWS files. The agreed fallback
  still applies (frame proxies in v1.0 if curating the frame is too slow).
- **S4, worker and WASM under the CSP (go).** A module worker lazily loads hash-wasm and
  `meshoptimizer/simplifier` under the production policy, on HTTPS and on the plain-HTTP LAN
  origin, with zero violations. `'wasm-unsafe-eval'` is required, and a worker obeys the CSP of its
  own script response. Hash with hash-wasm everywhere (same keys on LAN), post the `File` to the
  worker. See [s4-worker-csp.md](../spikes/s4-worker-csp.md).

## Known gaps and TODOs

**KWS Rack v2 entry** (`catalog/frames/kws-rack-v2.json`, marked `unverified`):

- `depthMm: 250` is a placeholder; `innerWidthMm: 222`, the ear spacing (236.525 mm), the hole
  pattern and the 1 mm hole tolerance are nominal values, not measured.
- Grams and print times per plate come from the designer's profile data via research, not from
  your slicer. The 3D part envelopes and the connector pieces per plate are guesses.
- The 7 rack-level magnets are counted once per rack, but where they go is unknown.
- No `source.license` yet (a validate warning), `stack.maxU: 30` is an assumption, and the frame
  has no joint gap or dead zone and no `assembly3d` rules, so 3D uses generic proxies.

**Other catalog entries:**

- All 13 items are `unverified`: U heights come from research, while plates, depth, slot positions
  and ear holes are estimates. None has hole offsets, so the editor will offer whole-U positions
  with an "unverified holes" badge.
- The Synology 4-bay KWS module has no designer credit (a validate warning).
- Some devices link to a maker's home page instead of a spec page; the MS-A2 brick output and the
  Raspberry Pi 5 height are approximate; the DeskPi PDU's DC input is assumed. The generic 10"
  frame's depth (300 mm) is a placeholder.

**Code and tooling:**

- The domain is not wired into the UI yet; the pages are placeholders (M2/M3a).
- BOM provenance numbers sections by stack position ("6U section #2", "Joint 3U #1 / 6U #2"),
  while stack messages and 3D labels say "Section 2 (6U)". Both are documented; pick one wording
  for the M3a UI if you prefer.
- `src/features/dev/spike-dnd/rackModel.ts` re-implements snapping and occupancy for the spike;
  M3b's `useRackDnd` should use `src/domain/placement.ts` instead.
- React Router logs "No `HydrateFallback` element provided" in dev, and the header wraps on a
  412 px phone (S2/S4 notes): app-shell work for M2.
- On plain-HTTP LAN origins Chrome logs a console error because COOP is sent everywhere (the plan's
  choice). The `prod-lan` E2E allow-lists exactly that message; sending COOP only over HTTPS would
  remove it (S4 request, not applied).
- 67 files are not in Prettier style (mostly shadcn-generated `components/ui`, the S1 parser written
  at 120 columns, `index.css`). CI does not check formatting; run `npm run format` once before the
  first commit if you want it uniform.
- SWA staging is not live and nothing is committed yet (both need you).
