## Integration pass (what changed)

**Wiring**

- `StatusBanners` is rendered in `#app-status-slot`, inside an error boundary of its own, so a
  broken banner never takes the page down.
- main.tsx plugs the Dexie diagnostics sink (200 rows, best effort: without IndexedDB the entries
  stay in memory) and calls `installPlanPersistence`, which registers the plan store's flush with
  the update prompt's `registerBeforeReload`, with the database drain and with page hide.
- The backup reminder shows on the Plans page once plans exist.
- Settings > Diagnostics reads the real diagnostics store, now including earlier sessions; reports
  name the catalog revision, and About links to Settings > Diagnostics.

**Bugs found and fixed**

- **CSP violation on every page.** With the persistence code in the first bundle, zod's
  `new Function` probe ran before main.tsx's jitless setup: Rolldown runs the chunks the entry
  imports before the entry's own body, and zod 4 probes when an object schema is built. The
  modules that build schemas (the plan store, the banners) now load lazily. Rule for later work:
  nothing main.tsx imports statically may build zod schemas at load (see the comment in main.tsx).
- **Restoring a backup could fail halfway** (engineer D's report): merge with settings or
  inventory but no custom parts threw `PrematureCommitError` after the plans were written. Every
  `await` inside the import transaction is now a Dexie promise (helpers plan rows; one function
  reads and writes). Regression tests added.
- **An edit followed by an immediate reload was lost** in Chromium: the save started on page hide
  never finishes. On hide the store now also writes a synchronous recovery copy, which the next
  load applies only if the stored revision still matches.
- **Edits after another tab's save notice did not count as unsaved**, so the banner said "Reload to
  see the latest version" while local edits were about to be lost. They now mark the plan unsaved.
- **Leaving the editor dropped those edits silently** (engineer A's open issue). The editor now
  asks (stay, leave without them, or save as a copy and leave) and arms the browser's prompt.
- **Destructive styles failed contrast** (about 4:1 in light, 4.2:1 in dark): the theme's
  destructive colour is now red-700 in light and red-300 in dark, so the kit's own variants pass;
  the plans feature's local workaround (`tones.ts`) is gone.
- A focus test in `ErrorBoundary.test.tsx` failed under load; it now waits for focus to move.

**Requests resolved**

- One clipboard helper (`src/lib/clipboard.ts`); the diagnostics copy and its test are removed.
- `updateSettings` takes a function patch inside its transaction; `settingsUpdate.ts` is removed.
- Backup metadata lives in `src/db/backupMetaRepo.ts` and `src/state/backupMeta.ts`; the settings
  feature keeps only the nudge rule (`backupNudgeRule.ts`).
- Backup and plan file names use the local date (`src/lib/date.ts`).
- `PlanSummary` carries the section heights, the frame name and the In my rack / To get counts,
  so plan cards no longer read and validate a whole plan each.
- `HaveNeed` and `LiveRegion` moved to `src/components/common`.
- The theme choice follows other open tabs.
- The mobile smoke test opens the Menu sheet before tapping About; a phone-width check of the
  Plans page was added.

## Known gaps and follow-ups

- **Bundle**: initial JS grew from about 154 kB to 196.7 kB gzip (Dexie, the diagnostics sink and
  the database status now load with the shell). Budget 300 kB.
- **Recovery copy**: kept in localStorage (about 5 MB per origin). A recovered edit is not
  undoable (history starts at the recovered plan). Edits made while a save was in flight come back
  only if the stored plan is exactly what that save wrote. If another tab opens the plan before a
  hidden tab's own save lands, that tab applies the copy and the hidden tab later shows a conflict
  banner: nothing is lost, but it can surprise.
- **Workers**: there is no production worker yet; worker diagnostics and `notifyNewVersion` on a
  worker's failed start come with M5/M7.
- **Diagnostics**: reports name the catalog revision once a page that loads the catalog has run
  (Plans, the wizard, the editor). A report copied on a fresh visit to Settings or About says
  "unknown". The plan's build-time `catalogRev` define (vite.config.ts) would fix that.
- **Wizard**: the Custom frame card and the "Fit my equipment" goal wait for M3b (the goal is shown
  as coming soon). Share links (`#p=`) show a note until the v0.2 viewer.
- **Recording mode** is kept per tab (sessionStorage), so a reload mid-recording stays in it but a
  new tab does not.
- **Backups**: `lastBackupAt` is recorded when the download is handed to the browser, not when the
  user keeps the file.
- **Root crashes**: when the layout itself fails, RouteError replaces the page without the header
  or the toaster (it shows its own Reload).
- `vite preview` still cannot serve the `prod-lan` host name, so `prod-lan` needs the container.
